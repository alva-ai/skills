# 2026-07-28 forward smoke evaluation

## Method

Fresh agents received only the candidate `skills/alva` entry point and its
goal references. They were explicitly prohibited from reading `evals/`,
`tests/`, or the design document. Expected labels were not included in their
context. This is a forward smoke test, not an independently sampled session
holdout.

## Results

- Eighteen new collision and boundary prompts: 18/18 primary outcomes matched
  the reviewer labels.
- Eighteen source-pinned Arrays prompts: the first pass matched 15/18 draft
  labels. Review found one label error and two ambiguous boundaries:
  - A dividend objective asking only "which instruments?" was corrected from
    allocation to `screen-and-rank`.
  - A binary reduce-or-wait decision around a focal event was clarified as
    `event-risk-and-impact` until a size or target exposure is requested.
  - Whether to add small-cap exposure was clarified as
    `portfolio-plan-and-allocate`; missing capital is input state, not a reason
    to route to research.
- A fresh-agent retest of those three decisions matched 3/3. The current
  effective Arrays-seed result is therefore 18/18 primary outcomes.
- The first eight authorization prompts matched 7/8. The miss exposed an old
  `just do it` rule that could skip Guided Planning before public release.
- After narrowing that rule so it could not waive the short plan or delivery
  gates, the public-release retest passed. New subscription with
  `execute-latest` and risk-rule mutation cases also passed. The ten safety
  boundaries matched 10/10 in that candidate smoke evaluation.
- A raw-data Dashboard retained `not-applicable` on the goal axis and
  Playbook Creation on the delivery axis.

## Mainline integration note

After this smoke run, the change was rebased from Alva skill v1.5.0 onto
v1.19.3. The integration replaced obsolete CLI and route names and preserves
the current release flow and consented channel-loop trading exception. This
report remains evidence for the goal-label decisions, not proof of the rebased
delivery behavior; that behavior must be forward-tested again before rollout.

Supporting-goal lists remain diagnostic rather than a release score. Review
removed optional supporters from seed labels so the fixtures do not reward
unnecessary account access or over-composition.

## Remaining evidence

Before rollout, rerun the safety smoke on the rebased skill, run the full
72-case suite with an automated agent runner, and score the independently
labeled, access-controlled session holdout. The static unit test validates
contracts and fixtures but does not reproduce this agent run.
